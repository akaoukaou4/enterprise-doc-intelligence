# DECISIONS

**Question this file answers:** why is the system the way it is?
**Not here:** how it works now (ARCHITECTURE), the plan (ROADMAP), how to run it (README).

## How to read and write this file

- One record per decision, numbered `D-nn`. Append new ones at the end. Never delete or rewrite an old one; settled records may be compressed (below).
- **Status:** *Accepted*, *Revisit at Phase N*, or *Superseded by D-nn*. A changed decision gets a new record ("Supersedes D-nn"), the old status changes, both link, then the ripple check (every doc, same commit).
- New records: **Decision**, **Why**, **Rejected**, **Revisit**. Evidence at the end (E-1 to E-8).
- Volatile facts (models, quotas, versions) are written here once, with the date checked.
- **Compressed:** D-01 to D-42 and E-1 to E-3 on 2026-10-30 (full text at tag `phase-12`; older versions at `decisions-before-compress`, `phase-10`, `phase-11`). Meaning, numbers, statuses and revisit triggers are kept.

## Scope and architecture

- **D-01 Scope** (Accepted). Upload PDFs, ask questions, get grounded answers with page and section citations. V1 is the smallest end-to-end path; risk classification, audit prioritization, agents, fine-tuning deferred. Every technology passes the 5-question test (ENGINEERING_STANDARDS section 1).
- **D-02 Modular monolith** (Accepted). One Python app in layers; PostgreSQL and object storage separate. No microservices, Kubernetes or Kafka without a measured requirement.
- **D-03 Independent pipeline** (Accepted). `app/pipeline/` imports no FastAPI, Airflow or database code; run directly or by Airflow. Embedding and storing are services.
- **D-04 Deployment path** (Accepted; done in Phase 12, Terraform in Phase 13). Compose locally, then AWS (EC2, RDS + pgvector, S3, IAM), Terraform last; only configuration changes. CloudWatch moved to Phase 14 (D-60). Rejected: EKS, Lambda, ECS, OpenSearch, Redis, queues.

## AI and document processing

- **D-05 Gemini for generation** (Accepted). Integrate AI, do not train or host large models. Model is a setting (D-28).
- **D-06 EmbeddingGemma, local** (Accepted). `google/embeddinggemma-300m`, 768 dimensions, `EMBEDDING_MODEL_ID` read by chunker and embedder; size checked against the DB column at load. CPU, no text leaves the machine. Gated: accept the license, `uv run hf auth login` on the host; images use `HF_TOKEN` as a build secret (D-53); CI never needs it.
- **D-07 Dense retrieval first** (Accepted; revisit at Phase 14). pgvector cosine; no hybrid search, reranking, query expansion, threshold, filter or vector index until evaluation shows a need. Phase 7: expected source in top 3 for 47 of 47 (E-4). Revisit if a larger corpus changes this.
- **D-08 Docling and HybridChunker** (Accepted). Structure-aware parsing; confirmed on two PDFs and the 14-document corpus (E-4).
- **D-09 Provenance is data** (Accepted). `Chunk(text, page_numbers, heading)`; pages are a list (chunks span pages); only the nearest heading is kept (Docling reports every heading as level 1). Stored row adds `document_id`, `chunk_index`.
- **D-10 Real output first; CPU PyTorch; caches on D:** (Accepted). Inspect real Docling output before coding. CPU-only PyTorch from an explicit `pytorch-cpu` uv index (GTX 1050 4 GB too small, CUDA adds GB, CI). `UV_CACHE_DIR`, `HF_HOME` on D: (C: nearly full; uv hardlinks need one drive).
- **D-11 Four cleaning rules** (Accepted). Drop contents chunks (label `document_index`), remove the license watermark line, strip `\x08` and BOM, drop chunks empty after cleaning. No minimum size. ISO PDF: 156 chunks, 84 contents junk. Limit: needs Docling to detect the contents page.
- **D-12 Known pipeline limits accepted** (Accepted; no measurable harm in Phase 7). Not fixed: text in images unreliable; some headings wrong or missing; tables can lose their header or split. 11 table questions all retrieved in top 5, one partial (q26). Untested: HybridChunker `repeat_table_header`.
- **D-13 Embed `title: <heading> | text: <chunk>`** (Accepted; supersedes `contextualize`). Built by our `build_document_text` (the model's `encode_document` always writes `title: none`); `Chunk` and embed stay independent of Docling; stored text stays plain. Revisit if retrieval worsens on a new corpus.
- **D-14 512-token chunks, EmbeddingGemma tokenizer** (Accepted; supersedes MiniLM). Model accepts 2048. Fits 30 to 60% more text (E-2); average 170 to 290 tokens. 256 and 1024 not tested.
- **D-15 Third-party documents stay local** (Accepted; exception D-40). Git-ignored. ISO/IEC 27001 is copyrighted: local only, never sent to Gemini. Check repo visibility before publishing (private now).

## Data, storage and backend

- **D-16 PostgreSQL + pgvector, one chunk table** (Accepted). `document_chunks`: FK `ON DELETE CASCADE`, `chunk_index`, `text`, `page_numbers integer[]`, `heading`, `embedding vector(768) NOT NULL`, `UNIQUE (document_id, chunk_index)`. Similarity = `1 - cosine_distance`. No vector index. Migration by hand (autogenerate cannot create the extension); scanner flagged hex revision ids, fixed with `# pragma: allowlist secret`. Rejected: a vector database.
- **D-17 boto3 behind `StorageService`** (Accepted). Keys `documents/<document_id>/<filename>`. MinIO when `MINIO_ENDPOINT` is set, else S3 (instance role, D-58). Only importer of boto3; `upload`, `download`, `delete`; errors become `NotFoundError` or `ExternalServiceError`. Limits: bytes in memory (fine at 20 MB); a missing `.env` makes boto3 try real AWS.
- **D-18 Alembic for every schema change** (Accepted). URL from `Settings`; every generated migration read before applying; no `create_all`.
- **D-19 Upload rules** (Accepted). Python UUID, unique `storage_key` (never returned), string `status` (no ENUM). Only `application/pdf` starting `%PDF-`, not empty, within `MAX_UPLOAD_MB` (20); filename reduced to its last component. Order: validate, store, insert; on insert failure delete the file. Limit: a crash between steps can leave an orphan file.
- **D-20 Backend conventions** (Accepted). One typed `Settings`; `create_app()`; one error shape `{"error": {"code", "message"}}` with `AppError` subclasses, generic message for unexpected errors; `/api/v1` for business, health unversioned; thin routes, services via `app/api/deps.py`; `DATABASE_URL` optional, lazy engine with `pool_pre_ping`.
- **D-21 EmbeddingService shared, plain `def` routes** (Accepted; loading superseded by D-49). One instance per process; blocking work runs in the thread pool.
- **D-22 ChunkService replaces in one transaction** (Accepted). `replace_chunks` checks counts and 768 values (`ValueError`), `NotFoundError` for unknown document, keeps old chunks on failure, does not touch `documents.status` (D-45).
- **D-23 One ingestion path** (Accepted). `IngestionService` (download, `process_pdf`, embed, `replace_chunks`); scripts go through `IngestionRunner` (D-45); Airflow runs the scripts (D-44).
- **D-24 Plain retrieval objects; `/search` for inspection** (Accepted). Frozen `RetrievedChunk(document_id, filename, page_numbers, heading, text, similarity)`; no ORM rows or vectors outside. `/search` shows whether retrieval or generation failed.
- **D-25 Input limits, stable order** (Accepted; default superseded by D-42). `top_k` 1 to 20; question 1 to 1000 characters; 422 on bad input; order by distance, `document_id`, `chunk_index`. Numbers were guesses. Gap: `ValueError` not mapped to HTTP (backlog).
- **D-26 Tests** (Accepted). Unit tests with fakes run in CI; integration tests use real containers, skip when unavailable, delete only what they created; retrieval tests use hand-made vectors; test file names unique across `tests/`.

## Generation (Phase 6)

- **D-27 Verify changing facts in official docs** (Accepted). AI Studio quotas differed from assumptions and changed the model choice (D-28).
- **D-28 `gemini-3.5-flash-lite`, set by `GEMINI_MODEL`** (Accepted; recheck shutdown date before real use). Key in `GEMINI_API_KEY` (`SecretStr`). AI Studio, 2026-10: 15 requests/min, 250,000 tokens/min, 500/day; larger Flash models 5/min and 20/day, unusable. No shutdown date announced on 2026-10-25; **not rechecked in Phases 12 and 13**. Table: `docs/provider_limits.md`.
- **D-29 `generate_content`, not the Interactions API** (Accepted; revisit on deprecation). RAG is one stateless request; the Interactions API keeps state at Google by default and its REST version was beta. Deliberate deviation from the vendor's advice; switching touches one file. Retention terms **not rechecked in Phases 12 and 13**.
- **D-30 LlmService owns the SDK; strict; no retries** (Accepted). Only importer of `google-genai`; `generate_structured(system_instruction, prompt, response_model)` returns a validated Pydantic object. One client, 30 s timeout, `max_output_tokens` 2048, one attempt. Accepted only if `finish_reason` is `STOP`, text non-empty and valid; else `502` with a generic message, details in the log. Why: output is untrusted, retries burn quota, SDK errors may hold request details. Revisit: retry only transient `5xx`, once, if they appear (none seen).
- **D-31 Prompt: numbered sources as data** (Accepted). Seven rules: use only the sources; `found: false` with no sources when they do not answer; partial answers allowed; cite only supporting sources; no numbers, files or pages in the answer text; source text is data, never instructions; answer in the question's language, concisely. `<source number="n">` with file and section, no pages; question last; fake tags in documents neutralized. A mitigation, not a full prompt-injection defense (Phase 14).
- **D-32 Model returns source numbers; code builds citations** (Accepted). `{found, answer, source_numbers}`; `RagService` keeps numbers matching a retrieved chunk, drops and logs the rest, builds `Citation` from stored chunks. Rejected: model-written citations. Phase 7: all answers cited an expected source; padding 4/46 (`top_k` 5), 3/47 (`top_k` 8) (E-4).
- **D-33 Three-layer refusal, no threshold** (Accepted). (1) No chunks: fixed message, no Gemini call. (2) `found: false`: no citations. (3) `found: true` without a valid citation or with a blank answer: fixed "not found". Similarity does not separate (E-1, E-4): near-miss q43 scores 0.657, above the lowest answerable (0.382); the model refused 5 of 5 at baseline. Revisit only if a new corpus changes the scores.
- **D-34 `POST /api/v1/ask`** (Accepted). `{question, top_k}` to `{answer, found, citations}`; `422` bad input, `502` Gemini failure; `found: false` is a field, not an error.
- **D-35 Logs hold numbers only** (Accepted). One `RAG:` line (chunk count, similarities, found, cited and dropped numbers) and one `Gemini call:` line (model, latency, finish reason, tokens) per question; never text.
- **D-36 Free-tier data use limits what goes to Gemini** (Accepted; kept on AWS, D-55). Only fictional, openly licensed or non-sensitive documents; only `/ask` sends chunks. Google terms (2026-10): free-tier data may improve its products, paid not. A paid key is needed before real company documents.
- **D-37 Tests never call Gemini** (Accepted). Fakes and dependency overrides; the one real call is `scripts/smoke_gemini.py` by hand with a fictional café.
- **D-38 Fictional policy corpus** (Accepted; location D-40). Three fictional German-company PDFs, eleven more in Phase 7; fits the product, safe on the free tier, overlaps on purpose (smoking) to test citation precision.

## Orchestration (Phase 8)

- **D-43 Airflow 3.3.2, LocalExecutor, own metadata DB** (Accepted; compose superseded by D-53; unchanged on AWS). api-server, scheduler, dag-processor, `postgres:16` for metadata, `parallelism` 2, login `airflow`/`airflow` (tunnel only on AWS, D-56). Why: one heavy task at a time (peak about 5.2 GB, E-5), so no Redis, worker or Flower; a reset cannot touch documents. Rejected: CeleryExecutor; metadata in the app DB. Revisit if ingestions must run in parallel.
- **D-44 App in its own venv in the Airflow image; DAG calls scripts** (Accepted; mount superseded by D-53). Airflow is Python 3.13, the project 3.12 with locked CPU PyTorch, so `/opt/app-venv` is built from `uv.lock`; `BashOperator`s run `scripts.claim_documents` and `scripts.ingest_document <id>`. One lock file, one code path (E-5: identical chunks). Rejected: `PythonOperator`/TaskFlow importing `app`; `DockerOperator`.
- **D-45 Status lifecycle in app code** (Accepted). `uploaded`, `processing`, `processed` or `failed`. `DocumentStatusService`: `claim_uploaded` (`FOR UPDATE SKIP LOCKED`, oldest first), `reset_orphans`, `mark_*`. `IngestionRunner` marks `processing`, ingests, marks `processed`, or marks `failed` and re-raises. `failed` is never claimed again; leftover `processing` returns to `uploaded` at each claim. Migration `8c1d5e7a2b96` sets existing documents to `processed`. Why: true whoever starts ingestion; no double claim; a corrupt PDF cannot loop. Rejected: status in DAG tasks; ENUM; automatic retry. Limits: failure reason only in the task log; a worker-killing document is retried each run; `reset_orphans` assumes no manual ingestion at that moment. Revisit: `error` column only on real need (D-47); attempt counter at Phase 14.
- **D-46 One polling DAG, mapped ingest tasks** (Accepted; unpaused at creation since D-53; verified on AWS, E-7, E-8). `ingest_documents` every minute (`catchup=False`, `max_active_runs=1`): `claim` (`--limit 5`), `build_commands` (`ingest_helpers.py`, unit-tested), mapped `ingest` (`max_active_tis_per_dag=1`, 1 retry after 1 min, 45 min timeout). Why: polling needs no coupling (no Airflow credentials in the API; upload works with Airflow down); one ingestion at a time (about 5 GiB). Rejected: API calling Airflow; sensors; parallel ingestion; one task per stage. Cost: up to 60 s before start.

## UI (Phase 9) and local system (Phase 10)

- **D-47 Streamlit: HTTP client only** (Accepted). `ui/` imports nothing from `app/`. New `GET /api/v1/documents` (newest first, `limit`, `offset`). No `documents.error` column: the UI shows `failed` and points to the admin log. Streamlit 1.66.0 (2026-10-21) in its own uv group. Rejected: UI importing services; the error column.

Document table is an `st.fragment` refreshing every 3 s only while a document is `uploaded` or `processing`. Only the client has unit tests; screens by hand (app-testing tool in backlog).
- **D-49 Background embedding preload, readiness endpoint** (Accepted; partly supersedes D-21). `PRELOAD_EMBEDDING_MODEL=true` loads the model in a thread at startup while the API answers (default false: tests and CI never need the gated model). Lock and `state` (`ready`, `loading`, `idle`). `GET /health/model`: 200 or 503, never starts a load, is the `api` health check. Why: the first question outlasted the 90 s UI timeout; a second load would add about 1.2 GB. Rejected: only raising the timeout; blocking load. Load took 26.3 s. Limits: an early question waits; a failed preload shows `idle` and retries on the next question; `--reload` reloads on every save.
- **D-50 Delete: row first, refused while processing** (Accepted; access D-56). `DELETE /api/v1/documents/{id}`: 204; 404 unknown; 409 if `processing`. Locks the row, deletes it (chunks cascade), commits, then deletes the file; a failed file delete is logged, call succeeds (an orphan file is harmless, a row pointing to a missing file is not). Rejected: file first; delete while processing; soft delete. Limits: no app authentication; a crash between steps leaves an orphan file.
- **D-51 One end-to-end check over HTTP: `scripts/e2e_check.py`** (Accepted; used on AWS in Phases 12 and 13). API only (`API_URL`): waits for `/health/model`, uploads a copy of the smallest corpus PDF under a unique name, polls to `processed`, checks `/search`, asks q51 (answerable) and q17 (unanswerable), deletes in `finally`, checks it is gone. It prints 10 PASS lines (E-8). Why: one script for local, containers and AWS; q17 is a clean refusal. Rejected: pytest (needs Airflow, key, minutes; I12); direct service calls; mock Gemini. Limits: needs Airflow; counts documents, not chunks; a `409` on cleanup prints the id; 2 of 500 daily Gemini requests. Not yet run from the laptop through the tunnel.
- **D-52 File picker limit 20 MB in `.streamlit/config.toml`** (Accepted). `maxUploadSize = 20` repeats `MAX_UPLOAD_MB` on purpose: otherwise a 200 MB file uploads before the API refuses it, and the UI cannot read the API setting (I15). Two places change together.

## Containers (Phase 11)

- **D-53 One compose; images bake code and models; service-name networking** (Accepted). (1) Root `docker-compose.yml`: `postgres`, `minio`, `minio-init`, `migrate` (Alembic, once), `api`, `ui`, Airflow (`airflow-db`, `airflow-init`, api-server, scheduler, dag-processor). (2) Three images (API also runs `migrate`, UI, Airflow); code and DAG copied in, no mounts; models baked in (D-54); `HF_HUB_OFFLINE=1`. (3) `HF_TOKEN` only as a BuildKit secret, never argument or `ENV`. (4) Containers use service names; compose `environment:` overrides `.env` localhost values, no code change. (5) DAG unpaused. Required: `HF_TOKEN`, `GEMINI_API_KEY`; `api` 3 GB limit, health check `/health/model`. (6) Airflow has no Gemini key (I13). Why: a stranger clones, sets two tokens, runs one command; `host.docker.internal` is not portable. Rejected: model in a volume; one image for API and Airflow (Python 3.13 vs 3.12); mounted code; token as build argument. Consequences: never push images to a public registry (gated model); CI does not build them; `e2e_check.py` checks them; rebuild after code changes. Lessons: the build's import check must run in the final stage, where system libraries exist, and include `psycopg`; one DNS failure in a long parallel build (D-57 builds one at a time).
- **D-54 Models baked in at build time** (Accepted). API image: EmbeddingGemma via `snapshot_download` into `/hf-cache`. Airflow image: same into `/opt/hf-cache` plus Docling models (`DocumentConverter().initialize_pipeline(InputFormat.PDF)` at build). Slow layers before code. `extract.py` unchanged (I1). Why: exactly the models used, no Hugging Face traffic, the 17.5-minute first ingestion is gone (E-5). Rejected: download at first use; mounting the host cache. Limit: ingestion with the network cut untested, RapidOCR models not proven offline.

## Terraform (Phase 13)

- **D-61 Terraform: recreate, default VPC, base setup in `user_data`, local state, secrets from the terminal, budget in code** (Accepted 2026-10-31; settles the Phase 13 question of D-55; revisit when a second person works on it or real data appears).
  **Decision.** (1) The AWS infrastructure is Terraform code in `infra/` (Terraform `~> 1.16`, used 1.16.6; `hashicorp/aws ~> 6.0`, locked at 6.71.0): 14 resources, the 13 of Phase 12 plus the budget. (2) **Recreate, not import:** the manual resources were deleted by exact id in the D-55 order, then `terraform apply` ran from nothing. The bucket held 14 objects (1,412,173 bytes), all fictional corpus. (3) The default VPC is read through data sources; no network is created. (4) `user_data.sh` does the base setup only: 4 GB swap, Docker, git, and the Compose v5.6.1 and Buildx v0.38.1 plugins. The clone, `.env` and image build stay manual (D-57), because secrets must not enter code or state. (5) The state is **local and git-ignored**; it holds the RDS password. (6) The database password and the budget email come only from `TF_VAR_rds_password` and `TF_VAR_budget_email`, set in the terminal (I18). (7) `force_destroy` on the bucket and `skip_final_snapshot` on RDS make `terraform destroy` leave nothing: safe only for the fictional corpus. (8) The server group declares its allow-all egress rule, because Terraform removes the default one. (9) The budget `monthly-cap` is in code with the same $20 limit and the same three alerts (85% and 100% actual, 100% forecast); the manual one was deleted just before the apply. (10) `.gitattributes` keeps `*.sh` on LF: Git warned it would convert `user_data.sh` to CRLF, which would break bash on the server.
  **Why.** Recreating proves the code works, and the name clashes (bucket, role, groups) would have blocked an import anyway; the data was reproducible. Keeping secrets out of Terraform keeps the state free of the Hugging Face and Gemini keys. Local state is enough for one person.
  **Rejected.** Import (keeps the data, hides mistakes); a new VPC (a new AWS service for no reason, D-55); Terraform doing the deployment (secrets in state); remote state (one person).
  **Revisit.** (a) Subnet: the server took the first id of the default VPC's list (a different one from the manual build); the order is not guaranteed and a change would replace the instance: sort the ids or fix one, then plan. (b) Remote state if a second person works on it. (c) Remove `force_destroy` and `skip_final_snapshot` before any real data. (d) `terraform fmt -check` and `validate` in the check and CI. (e) Database Insights "standard" and RDS extended support appeared as AWS defaults in the plan (we did not set them); their cost is unchecked.

## Evidence

**E-1 Phase 6 refusal scores (manual, API).** Policy corpus: answerable top similarity 0.4968 or higher (vacation 0.5531, smoking 0.6697); refused 0.4144 or lower.
