# DECISIONS

**Question this file answers:** why is the system the way it is?
**Not here:** how it works now (ARCHITECTURE), the plan (ROADMAP), how to run it (README).

## How to read and write this file

- One record per decision, numbered `D-nn`. Append new ones at the end. Never delete or rewrite an old one (settled records may be compressed, see below).
- **Status:** *Accepted*, *Revisit at Phase N* (accepted, with a known trigger to look again), or *Superseded by D-nn*. When a decision changes, add a new record that says "Supersedes D-nn", and change the old status. Link both ways. Then run the ripple check: fix every doc that mentions the old decision, in the same commit.
- New records use the shape **Decision**, **Why**, **Rejected**, **Revisit**. Evidence tables are at the end (E-1 to E-7).
- Volatile facts (model names, quotas, versions) are written here once, with the date they were checked.
- **Compressed records.** D-01 to D-42 were compressed on 2026-10-22 (full text in Git at the tag `decisions-before-compress`) and again on 2026-10-30. D-43 to D-52 and E-1 to E-3 were compressed on 2026-10-26 (full text at the tag `phase-10`). D-53, D-54 and E-4 to E-6 were compressed on 2026-10-30 (full text at the tag `phase-11`). Meaning, numbers, statuses and revisit triggers are kept.
- Section numbers of the very old file no longer exist. That file is in Git at the tag `docs-before-restructure`.

## Scope and architecture

- **D-01 · Product and V1 scope** (Accepted). A document-intelligence assistant: upload PDFs, ask questions, get grounded answers with page and section citations. V1 is the smallest end-to-end path. Risk classification, audit prioritization, agents, fine-tuning and advanced automation are deferred. Every technology passes the 5-question test (ENGINEERING_STANDARDS section 1).
- **D-02 · Modular monolith** (Accepted). One Python app with internal layers; PostgreSQL and object storage as separate services. No microservices, Kubernetes or Kafka. Revisit only on a measured requirement.
- **D-03 · Independent pipeline, two execution modes** (Accepted). `app/pipeline/` imports no FastAPI, Airflow or database code. Direct mode: scripts and tests. Orchestrated mode: Airflow runs the same code (Phase 8). Embedding and storing are services, not pipeline.
- **D-04 · Deployment path** (Accepted; Phase 12 done, see D-55). Docker Compose locally first, then AWS (EC2, RDS PostgreSQL + pgvector, S3, IAM, CloudWatch), Terraform last. Same app, only configuration changes. Phase 12 followed this path with two changes: CloudWatch moved to Phase 14 (D-60) and Terraform stays in Phase 13. Rejected: EKS, Lambda, ECS, OpenSearch, Redis, queues.

## AI and document processing

- **D-05 · Gemini for generation** (Accepted). The project integrates AI, it does not train or host large models. The model is one setting (D-28).
- **D-06 · EmbeddingGemma, local, one setting** (Accepted). `google/embeddinggemma-300m`, 768 dimensions, set by `EMBEDDING_MODEL_ID`, read by both the chunker tokenizer and the embedding service; the size is checked against the database column when the model loads. Runs on CPU and sends no document text out. The model is gated: accept the license and run `uv run hf auth login` once on the host; the images are built with `HF_TOKEN` as a build secret and run offline (D-53); CI never needs it. Phase 7 gave no reason to change it (E-4).
- **D-07 · Dense retrieval first, evaluate before optimizing** (Accepted; revisit at Phase 14). pgvector cosine similarity. No hybrid search, reranking, query expansion, threshold, document filter or vector index until evaluation shows a need. Phase 7: the expected source was in the top 3 for all 47 answerable questions (E-4). Revisit only if a larger corpus changes this.
- **D-08 · Docling and HybridChunker** (Accepted). Structure-aware parsing suits enterprise documents; confirmed on two PDFs and the 14-document corpus (E-4). Revisit if a later corpus shows chunking hurts retrieval.
- **D-09 · Provenance is part of the data** (Accepted). `Chunk(text, page_numbers, heading)`; `page_numbers` is a list because chunks span pages; only the nearest heading is kept (Docling reports every heading as level 1). The stored row adds `document_id` and `chunk_index`.
- **D-10 · Real output first; CPU PyTorch; caches on D:** (Accepted). Inspect real Docling output before writing pipeline code. CPU-only PyTorch from an explicit `pytorch-cpu` uv index (the GTX 1050 with 4 GB is too small, CUDA wheels add GB and CI would download them). `UV_CACHE_DIR` and `HF_HOME` on D: (C: is nearly full; uv hardlinks need one drive).
- **D-11 · Four cleaning rules, each backed by data** (Accepted). Drop table-of-contents chunks (label `document_index`), remove the license watermark line, strip `\x08` and the byte-order mark, drop chunks empty after cleaning. No minimum chunk size. The ISO PDF gave 156 chunks, 84 of them contents junk. Limit: works only when Docling detects the contents page.
- **D-12 · Known pipeline limits accepted** (Accepted; Phase 7: no measurable harm). Not fixed: text and tables inside images are unreliable; some headings are wrong or missing; tables can lose their header row or split across chunks; rows without separator lines merge. 11 table questions: all retrieved in the top 5, answers correct except one partial (q26). Candidate fix, untested: HybridChunker `repeat_table_header`.
- **D-13 · Embed `title: <heading> | text: <chunk>`, built by our code** (Accepted; supersedes the Phase 3 plan to embed `chunker.contextualize(chunk)`). `build_document_text` builds the model's native format from our `Chunk` (the model's own `encode_document` always writes `title: none`). Keeps `Chunk` unchanged and the embed stage independent of Docling; without a heading it equals the model's prompt (cosine 1.0000). Stored `text` stays plain. Revisit if retrieval gets worse on a new corpus.
- **D-14 · 512-token chunks measured with the EmbeddingGemma tokenizer** (Accepted; supersedes the MiniLM tokenizer). The model accepts 2048 tokens; the budget is 512. Its larger vocabulary fits 30 to 60% more text (E-2); average chunk 170 to 290 tokens. 256 and 1024 were not tested. Revisit only if retrieval gets worse.
- **D-15 · Third-party sample documents stay local** (Accepted; exception D-40). PDFs and Docling output stay in git-ignored folders. The ISO/IEC 27001 standard is copyrighted: local use only, never sent to Gemini. The repository is private now (public at the time of writing the README; check before publishing).

## Data, storage and backend

- **D-16 · PostgreSQL + pgvector, one table of chunks** (Accepted). `document_chunks`: `document_id` FK `ON DELETE CASCADE`, `chunk_index`, `text`, `page_numbers integer[]`, `heading`, `embedding vector(768) NOT NULL`, `UNIQUE (document_id, chunk_index)`. Similarity is `1 - cosine_distance`. No vector index (D-07). Rejected: a dedicated vector database. The migration was written by hand (autogenerate cannot create the extension); the secret scanner flagged its hex revision ids, fixed with an inline `# pragma: allowlist secret`.
- **D-17 · Object storage through boto3 and a small `StorageService`** (Accepted). Originals live under `documents/<document_id>/<filename>`. boto3 talks to MinIO when `MINIO_ENDPOINT` is set, to real S3 otherwise (instance role on AWS, D-58). Only importer of boto3; `upload`, `download`, `delete`; lazy client; errors mapped to `NotFoundError` or `ExternalServiceError`. No interface class. Limits: files are bytes in memory (fine at 20 MB); a missing `.env` makes boto3 try real AWS; the `MINIO_*` names may become `S3_*` later.
- **D-18 · Alembic for every schema change** (Accepted). Migrations in `migrations/`, URL from `Settings`, `versions/` excluded from Ruff, every generated migration read before applying. No `create_all`.
- **D-19 · Upload rules and document model** (Accepted). Python-generated UUID, unique `storage_key` (never returned), plain-string `status` (not an ENUM). Accept only `application/pdf` whose bytes start with `%PDF-`, not empty, within `MAX_UPLOAD_MB` (20). Filename reduced to its last path component. Order: validate, store the file, insert the row; if the insert fails, roll back and delete the file. Limit: a crash between the two steps can leave an orphan file.
- **D-20 · Backend conventions** (Accepted). One typed `Settings`; settings added only when a phase needs them. `create_app()` factory. One error shape `{"error": {"code", "message"}}` with `AppError` subclasses; unexpected exceptions return a generic message. Business endpoints under `/api/v1`, health endpoints unversioned. Thin routes, logic in services injected through `app/api/deps.py`. `DATABASE_URL` optional and the engine lazy with `pool_pre_ping`.
- **D-21 · EmbeddingService: shared, behind plain `def` routes** (Accepted; the loading part is superseded by D-49). One instance per process (`lru_cache`); search and ask routes are plain `def`, so blocking work runs in the thread pool. The offline run is settled by D-53.
- **D-22 · ChunkService replaces in one transaction, validates first** (Accepted). `replace_chunks` checks counts and 768 values (`ValueError`), raises `NotFoundError` for an unknown document, deletes old chunks and inserts new ones in one transaction, keeps the old chunks on any failure. It does not change `documents.status` (D-45).
- **D-23 · One ingestion code path** (Accepted). The four calls (download, `process_pdf`, `embed_documents`, `replace_chunks`) live in `IngestionService` since a second caller appeared; both scripts go through `IngestionRunner` (D-45), which also sets the status. Airflow runs these same scripts (D-44).
- **D-24 · Retrieval returns plain objects; `/search` is an inspection endpoint** (Accepted). `RetrievalService.search` returns frozen `RetrievedChunk(document_id, filename, page_numbers, heading, text, similarity)`, with the file name joined in the query. Callers never see ORM rows or vectors. `/search` shows whether retrieval or generation failed.
- **D-25 · Input limits and stable ordering** (Accepted; default `top_k` superseded by D-42). `top_k` 1 to 20; question stripped, 1 to 1000 characters; constants in `retrieval.py`; API returns 422. Order by distance, `document_id`, `chunk_index`, so tests and evaluation repeat. The numbers were guesses. Known gap: `ValueError` is not mapped to HTTP (backlog).
- **D-26 · Tests: fakes, hand-made vectors, skipped integration, unique names** (Accepted). Unit tests use fakes and run in CI. Integration tests use the real containers, skip themselves when unavailable and delete only what they created. Retrieval integration tests use hand-made vectors (similarity 1.0, 0.7071, 0.0). Test file names are unique across `tests/`.

## Generation (Phase 6)

- **D-27 · Check changing facts in official documentation first** (Accepted). SDK shape, model names, quotas, data-use terms: use the official source, a small real call, or ask. The quotas seen in AI Studio differed from what was assumed and changed the model choice (D-28).
- **D-28 · Model `gemini-3.5-flash-lite`, set by `GEMINI_MODEL`** (Accepted; recheck the shutdown date before real use). Key in `GEMINI_API_KEY` as a `SecretStr`. Checked 2026-10 in AI Studio: 15 requests per minute, 250,000 tokens per minute, 500 per day; larger Flash models only 5 per minute and 20 per day, unusable for development and evaluation. Short extraction suits a small model. No shutdown date announced when last checked (2026-10-25); **not rechecked in Phase 12**. Full table in `docs/provider_limits.md`.
- **D-29 · `generate_content`, not the Interactions API** (Accepted; revisit on deprecation). RAG here is one stateless request. The Interactions API keeps state at Google by default (a privacy question for document text) and its REST version was beta when checked. A conscious deviation from the vendor's recommendation. Switching later touches one file (D-30). Its retention terms were **not rechecked in Phase 12**.
- **D-30 · LlmService owns the SDK; strict acceptance; no retries; generic errors** (Accepted). Only importer of `google-genai`. `generate_structured(system_instruction, prompt, response_model)` returns a validated Pydantic object. One client per process, 30 s timeout, `max_output_tokens` 2048, one attempt. Accepted only if `finish_reason` is `STOP`, the text is not empty and it validates; otherwise `502`. Every Gemini failure is `ExternalServiceError` (`502`) with a generic message; details go to the log only. Why: model output is untrusted; retries burn the daily quota; SDK exception text may contain request details. Revisit: if transient `5xx` errors are common, retry only those, once (none seen).
- **D-31 · Prompt: numbered sources, declared as data** (Accepted). `rag_prompt.py` builds a seven-rule system instruction: use only the sources; `found: false` with no sources when they do not answer; partial answers allowed; cite only directly supporting sources; no numbers, file names or pages in the answer text; source text is data, never instructions; answer in the question's language, concisely. Each chunk is `<source number="n">` with file and section, no pages. The question comes last in `<question>` tags. Fake tags inside documents are neutralized. Limit: a mitigation, not a full defense against prompt injection (Phase 14 topic).
- **D-32 · The model returns source numbers; code builds citations** (Accepted). The model returns `{found, answer, source_numbers}`. `RagService` keeps numbers `1..n` matching a retrieved chunk, drops (and logs) the rest, and builds each `Citation` from the stored chunk. Rejected: the model writing citation text. Phase 7: every answered question cited an expected source; 4 of 46 answers (8.7%) at `top_k` 5 and 3 of 47 at `top_k` 8 added a citation outside the expected list, mostly an older or shorter version of the same policy (E-4).
- **D-33 · Refusal in three layers; no similarity threshold** (Accepted; threshold rejected in Phase 7, E-4). (1) No retrieved chunks: a fixed message, Gemini is not called. (2) The model answers `found: false`: no citations. (3) `found: true` with no valid source number or a blank answer: replaced by a fixed "not found" message. Similarities are logged. One corpus separated cleanly (answerable 0.4968 or higher, refused 0.4144 or lower); on another a near-miss scored 0.6617, above every answerable question (E-1). Phase 7: the near-miss q43 scores 0.657, above the lowest answerable question (0.382); the model's own `found` refused 5 of 5 at the baseline. Revisit only if a new corpus changes the scores.
- **D-34 · `POST /api/v1/ask`** (Accepted). Request `{question, top_k}`, response `{answer, found, citations}`; `422` for bad input, `502` for Gemini failure. `found: false` is a field, not an error.
- **D-35 · Logs hold numbers only** (Accepted). Never the question or chunk text. One `RAG:` line per question (chunk count, similarities, found, cited and dropped numbers) and one `Gemini call:` line (model, latency, finish reason, token counts).
- **D-36 · Free-tier data use decides which documents go to Gemini** (Accepted; Phase 12: free tier kept, see D-55). Only fictional, openly licensed or non-sensitive documents go through `/ask`; ingestion, embeddings and `/search` run locally, only `/ask` sends the retrieved chunks. Google's terms (checked 2026-10): free-tier prompts and responses may be used to improve its products; paid tier not. A paid key is needed before real company documents.
- **D-37 · Tests never call Gemini** (Accepted). Fake client for `LlmService`, plain chunks for the prompt, fake services for `RagService`, dependency overrides for the endpoint; the evaluation runner the same. The one real call is `scripts/smoke_gemini.py`, by hand, with a fictional café.
- **D-38 · Test corpus: fictional policy documents** (Accepted; location amended by D-40). Three fictional German-company policy PDFs first, eleven more in Phase 7. They are what the product is for, they are fictional (so the free tier is safe), and several overlap on purpose (smoking) to test citation precision.

## Evaluation (Phase 7)

- **D-41 · Evaluation design: separate retrieval and generation, correctness by hand** (Accepted, 2026-10-18). `data/eval/questions.json` version 5: 52 questions, 47 answerable and 5 to refuse. Kinds: overlap 16, single passage 13, table 11, multi-passage 3, cross-language 4 (German, French, Spanish), refusals (near-miss 3, not answerable 2). Retrieval is measured from one top-20 search per question (hit at 1, 3, 5, 10, MRR); generation separately (answered, refused, citation coverage, padding, precision). Correctness is read by hand. Contradictions inside the corpus are tests on purpose. The runner calls the services directly, writes the result file after every question, waits 5 s between Gemini calls and stops after 3 failures in a row. Rejected: literal matching of expected facts (0 of 46 matched); grading with a second LLM; a refusal threshold (D-33). Limits: source matching is page-level; a qualified answer (q16, q24) is judged by hand.
- **D-42 · Default `top_k` is 8** (Accepted, 2026-10-18; supersedes the default of 5 in D-25). At 5, q07 (who is the Works Council chair) was refused: the contact tables of four files rank 6 to 9 (similarity 0.343 to 0.347, just below rank 5 at 0.351). At 8 it is answered correctly (E-4). Cost: up to 8 chunks per prompt. Rejected: 10 (untested); keeping 5 and merging contact chunks (a chunking change). Revisit if token use or free-tier limits matter, or a larger corpus changes the picture.

## Orchestration (Phase 8)

- **D-43 · Airflow 3.3.2, LocalExecutor, own metadata database** (Accepted 2026-10-18; compose and host access superseded by D-53; unchanged on AWS). api-server, scheduler, dag-processor and its own `postgres:16` for metadata; LocalExecutor, `[core] parallelism` 2, no examples, login `airflow` / `airflow` (default; reachable only through the tunnel on AWS, D-56). Why: ingestion is one heavy task at a time (peak about 5.2 GB, E-5), so no Redis, worker or Flower; a separate metadata database means a reset cannot touch documents. Rejected: CeleryExecutor; Airflow metadata in the application database. Revisit if ingestions must run in parallel.
- **D-44 · The app runs in its own virtual environment in the Airflow image; the DAG calls the scripts** (Accepted 2026-10-18; the code mount is superseded by D-53). Airflow runs Python 3.13; the project needs 3.12 and the locked CPU PyTorch, so `/opt/app-venv` is built from `uv.lock`. DAG tasks are `BashOperator`s running `python -m scripts.claim_documents` and `python -m scripts.ingest_document <id>` in it. Why: one lock file and one code path (E-5: identical chunks). Rejected: `PythonOperator` or TaskFlow importing `app`; `DockerOperator` (needs the Docker socket).
- **D-45 · The status lifecycle lives in app code, not in Airflow** (Accepted 2026-10-20). Status: `uploaded`, `processing`, then `processed` or `failed`. `DocumentStatusService` has `claim_uploaded` (`SELECT ... FOR UPDATE SKIP LOCKED`, oldest first), `reset_orphans` and `mark_*`. `IngestionRunner` marks `processing`, calls `IngestionService`, then marks `processed`, or marks `failed` and re-raises. A `failed` document is never claimed again; `reset_orphans` turns leftover `processing` documents back to `uploaded` at each claim. Migration `8c1d5e7a2b96` sets already ingested documents to `processed`. Why: the status must be true whoever starts the ingestion; `SKIP LOCKED` means no document is claimed twice; a final `failed` stops a corrupt PDF from looping. Rejected: status updates inside DAG tasks; an ENUM; automatic retry of failed documents. Limits: the failure reason is only in the Airflow task log; a document that kills the worker is retried at every run; `reset_orphans` assumes no manual ingestion at the same moment. Revisit: an `error` column only if a real need appears (D-47); an attempt counter at Phase 14.
- **D-46 · One polling DAG: claim, then one mapped ingest task per document** (Accepted 2026-10-20; created unpaused since D-53; unchanged on AWS, verified by E-7). DAG `ingest_documents` every minute (`catchup=False`, `max_active_runs=1`). `claim` runs `scripts.claim_documents --limit 5`; `build_commands` (`airflow/dags/ingest_helpers.py`, unit-tested in CI) turns the ids into commands; `ingest` is a mapped `BashOperator`, `max_active_tis_per_dag=1`, `retries=1` after 1 minute, `execution_timeout` 45 minutes. Why: polling gives "starts by itself" with no coupling (no Airflow credentials in the API; upload works while Airflow is down); one ingestion at a time because one peaks at about 5 GiB (E-5, E-7). Rejected: the API calling the Airflow REST API; a sensor or event trigger; parallel ingestion (memory); one task per stage. Cost: up to 60 s between upload and the start of ingestion.

## UI (Phase 9)

- **D-47 · Streamlit UI: HTTP client only, list endpoint, own dependency group** (Accepted 2026-10-22). `ui/` calls the API over HTTP only and imports nothing from `app/`. New `GET /api/v1/documents` (newest first, `limit`, `offset`). No `documents.error` column: the UI shows `failed` and a fixed line that points to the admin log. Streamlit is in its own uv dependency group (1.66.0 checked 2026-10-21), so the Airflow image never needs it. Rejected: the UI importing the services; the error column (no measured need).
- **D-48 · UI build choices: client module, polling fragment, ask form, invariant I15** (Accepted 2026-10-23). `ui/api_client.py` is the only code that speaks HTTP; `ui/app.py` only draws. Timeouts: 15 s list, 60 s upload, 90 s ask; a failure becomes an `ApiError` with a short safe message. The document table is an `st.fragment` with `run_every` 3 s only while a document is `uploaded` or `processing`. The question is a form. Only the client has unit tests; the screens are checked by hand. Rejected for now: Streamlit's app-testing tool (backlog).
- **D-49 · Embedding model preloaded in the background, with a readiness endpoint** (Accepted 2026-10-23; partly supersedes D-21). With `PRELOAD_EMBEDDING_MODEL=true` the API loads the model in a background thread at startup and answers requests at once (default false, so tests and CI never need the gated model). `EmbeddingService` has a lock and a `state` (`ready`, `loading`, `idle`). `GET /health/model` returns 200 `ready` or 503 `loading` / `idle`, never starts a load, and is the `api` container health check. Why: the first question waited longer than the 90 s UI timeout, and a second load would double the weights in memory (about 1.2 GB). Rejected: only raising the UI timeout; a blocking load at startup. Evidence: model loaded in 26.3 s. Limits: a question in the first seconds waits for the load; a failed preload shows `idle` and the next question retries; `--reload` reloads the model on every save.

## Complete local system (Phase 10)

- **D-50 · Delete a document: row first, then file; refused while processing** (Accepted 2026-10-24; access decision: D-56). `DELETE /api/v1/documents/{id}` returns 204. `DocumentService.delete` locks the row (`SELECT ... FOR UPDATE`), refuses with 409 when `status` is `processing`, deletes the row (chunks cascade), commits, then deletes the file. Unknown id: 404. A failed storage delete is logged and the call still succeeds (an orphan file is harmless, a row pointing to a missing file is not). Rejected: file first, then row; deleting while `processing`; soft delete. Limits: no authentication in the app (the network closes the access on AWS, D-56); a crash between the two steps leaves an orphan file.
- **D-51 · One end-to-end check over HTTP: `scripts/e2e_check.py`** (Accepted 2026-10-24; used on AWS in Phase 12). It talks to the API only (`API_URL`): waits for `/health/model`, uploads a copy of the smallest corpus PDF under a unique name, polls until `processed`, checks `/search`, asks one answerable (q51) and one unanswerable question (q17) through `/ask`, deletes the document in a `finally` block, checks it is gone and the count is back. Why: over HTTP the same script checks the local stack, the containers and AWS; q17 is a clean refusal (near-misses belong to the evaluation). Rejected: a pytest test (needs Airflow, a Gemini key and minutes; I12); calling services directly; a mock Gemini. Limits: needs Airflow running; counts documents, not chunks; a `409` on cleanup leaves the document and prints its id; 2 of the 500 daily free Gemini requests. Not yet run from the laptop through a tunnel.
- **D-52 · The file picker limit is 20 MB, set in `.streamlit/config.toml`** (Accepted 2026-10-24). `[server] maxUploadSize = 20`, repeating `MAX_UPLOAD_MB` of the API on purpose: without it a 200 MB file is uploaded before the API refuses it, and the UI cannot read the API's setting (I15). The UI image carries the file and starts in `/app`. Limit: two places must change together.

## Containers (Phase 11)

- **D-53 · One compose for the whole system; images bake the code and the models; service-name networking** (Accepted 2026-10-26; the registry, secrets and ports questions are settled in Phase 12 by D-57 and D-56). (1) The root `docker-compose.yml` starts everything: `postgres`, `minio`, `minio-init`, `migrate` (Alembic, once), `api`, `ui`, and Airflow (`airflow-db`, `airflow-init`, api-server, scheduler, dag-processor). (2) Three images: API (also runs `migrate`), UI, Airflow. Code and DAG are copied in (no mounts); models are baked in at build time (D-54); `HF_HUB_OFFLINE=1`. (3) `HF_TOKEN` reaches the build only as a BuildKit secret (compose `secrets`, taken from the environment), never a build argument or `ENV`, so it is in no layer. (4) Containers reach each other by service name; the compose `environment:` overrides the `localhost` values of `.env` inside containers, so no code changed. (5) The DAG is created unpaused. Only `HF_TOKEN` and `GEMINI_API_KEY` are required; `api` has a 3 GB memory limit and the health check `/health/model`. (6) Airflow keeps its own metadata database (D-43); it gets no Gemini key (I13). Why: acceptance test written first: a stranger clones, sets two tokens, runs one command; `host.docker.internal` is a Docker Desktop feature, not portable to Linux. Rejected: the model in a volume filled by an init step; one shared image for API and Airflow (Python 3.13 against 3.12, D-44); mounted code; the token as a build argument. Consequences: the images contain a gated model, so never push them to a public registry; CI does not build them (no token in CI); `scripts/e2e_check.py` is their check; after a code change run `docker compose up -d --build`. Build lessons: the import check that fails the build runs in the final stage, where the system libraries exist, and imports `psycopg` too (a check in the wrong stage proved nothing); one build step failed once with a DNS error after a very long parallel build, and the retry passed (D-57 builds one image at a time).
- **D-54 · Models are baked into the images at build time** (Accepted 2026-10-26). API image: EmbeddingGemma via `snapshot_download` into `/hf-cache` with the token as a build secret. Airflow image: the same for `/opt/hf-cache`, and the Docling models by starting its PDF pipeline once at build (`DocumentConverter().initialize_pipeline(InputFormat.PDF)`). Slow layers come before the code layers. `extract.py` is unchanged (I1). Why: the pipeline downloads exactly the models it uses, the container needs no internet for Hugging Face, and the 17.5-minute first ingestion (E-5) is gone. Rejected: downloading at first use; mounting the host cache. Limit: ingestion with the network cut was not tested, so the RapidOCR models are not proven offline. Revisit if a later Docling version changes where models are stored.

## AWS deployment (Phase 12)

- **D-55 · AWS shape: one EC2 server runs the same compose; RDS and S3 replace the local services; built by hand first; one region** (Accepted 2026-10-30; amends D-04 and settles the Phase 12 part of D-36; revisit at Phase 13).
  **Decision.** (1) One EC2 instance runs the three images with `docker-compose.yml` plus `docker-compose.aws.yml` (D-58); RDS PostgreSQL replaces the local database; S3 replaces MinIO; IAM role for the instance; Gemini stays external. (2) Everything is in `eu-north-1` (the console was already there, and the free-plan instance list was checked there, E-7). (3) The resources were created **by hand** in the console, with a written inventory and delete order (ARCHITECTURE 12.2), and Terraform recreates them in Phase 13. (4) The Gemini free tier stays: only the fictional corpus goes to AWS.
  **Why.** Understand each service before coding it; the same compose and images mean no redesign (PROJECT portability principle); ENGINEERING_STANDARDS section 11 asks for infrastructure as code, and the inventory with delete order keeps the manual phase teardown-safe until Terraform exists. A second region would add transfer cost and latency.
  **Rejected.** ECS/Fargate, EKS, Lambda (D-04); PostgreSQL in compose on EC2 (cheaper, but skips the RDS mapping); a registry (D-57); a paid Gemini key (no real data).
  **Revisit.** Phase 13 (recreate or import); a paid key before real company documents. The Gemini model shutdown date and the Interactions API retention terms were not rechecked in Phase 12 (D-28, D-29; backlog).
- **D-56 · Access: no inbound port, SSM tunnel, no login in the app** (Accepted 2026-10-30; settles the access question of D-50 and D-53; revisit when real users appear). The server's security group has **0 inbound rules** (no SSH, no public URL); the database group allows 5432 only from the server group; RDS is not publicly accessible (invariant I17, checked in the console, E-7). The server's shell and the UI are reached through SSM Session Manager (instance role with `AmazonSSMManagedInstanceCore`). The laptop uses `aws login` (console sign-in, temporary credentials, `aws logout` when done) and an SSM port forward (UI on local port 18501, because the local compose uses 8501). Why: the upload, delete and the default Airflow login must not be reachable by anyone (ROADMAP Phase 12); PROJECT.md excludes complex authentication; this closes the risk with no code. Rejected: SSH (needs an open port and a key); a public URL behind app login (needs auth code, TLS and a domain); an IP-restricted security group (an address that changes). Limits: a demo for others is a recording, not a link; the CLI runs as the account's full-access role (`AccountFullAccessRole`), a restricted IAM user is in the backlog; the console MFA was set after a clock fix on the phone. Revisit if real users appear (authentication, TLS).
- **D-57 · Build on the instance, no registry; secrets in `.env` (mode 600); clone with a one-use token** (Accepted 2026-10-30; settles the registry and secrets questions of D-53). The images are built on the server with `HF_TOKEN` as a build secret and `COMPOSE_PARALLEL_LIMIT=1` (one image at a time; a parallel build on an HDD once failed with a DNS error, and the instance has 2 vCPUs). The repository is private, so the clone uses a GitHub fine-grained token (Contents read-only, one repository, 30 days), typed at a hidden prompt and removed from the remote URL after the clone. The server's `.env` (RDS host, RDS password, `HF_TOKEN`, `GEMINI_API_KEY`) is written from hidden prompts, so no secret is in the chat, the shell history or Git. Why: the model is gated and the images must never reach a public registry; a private registry (ECR) is one more service for one server; a stopped-and-started server needs no rebuild. Rejected: ECR; `docker save` and copy (15 GB or more); a secret store now. Revisit: a secret store (SSM Parameter Store) in Phase 14; revoke the GitHub token after Phase 13.
- **D-58 · `docker-compose.aws.yml`: profile for local services, empty storage keys, RDS over SSL, `check-yaml --unsafe`** (Accepted 2026-10-30). The override gives `postgres`, `minio` and `minio-init` the profile `local`; `migrate`, `api` and the scheduler get `DATABASE_URL` for RDS (`sslmode=require`; a password of letters and digits only, because symbols break the URL), the bucket and `AWS_DEFAULT_REGION=eu-north-1`, with `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY` and `MINIO_SECRET_KEY` empty, so `StorageService` builds a plain S3 client that uses the instance role (D-17, no code change). The `depends_on` lines that named removed services are cut with the Compose tags `!reset` and `!override`. Containers read the role credentials through the metadata service, so the instance sets IMDSv2 with a **hop limit of 2** (the default of 1 would stop them). The IAM policy allows Get, Put and DeleteObject on the bucket's objects and ListBucket on the bucket (without ListBucket a missing key looks like "denied"). The pre-commit `check-yaml` hook cannot read the Compose tags, so it runs with `--unsafe` (syntax only). Why: no change to the base file or the code; the same images. Rejected: a second full compose file (two files to keep equal); access keys in the containers. Limit: the override file does not remove `airflow-db`; the stack still starts its own metadata database.
- **D-59 · Compute: `m7i-flex.large` (8 GiB) with a 4 GB swap file, on the Free plan** (Accepted 2026-10-30; revisit if two ingestions must run at once). The Free plan limits the EC2 types (the launch form listed `t3.micro` 1 GiB, `t3.small` 2, `c7i-flex.large` 4 and `m7i-flex.large` 8 GiB; third-party sources from 2025 say `xlarge` and above are blocked). The Phase 11 plan assumed 16 GB. The system needs about 2.4 GiB at idle and 4.3 GiB more during one ingestion (E-6), the same margin as the 8 GB Docker VM where everything already passes, so 8 GiB was tried first with a swap file for the peaks (the 50 GiB disk is enough). Evidence: the corpus ingestion peaked at 7.1 GiB used with 237 MiB available and 642 MiB of swap in use, and nothing was killed (E-7). Rules: one ingestion at a time (D-46); nothing heavy during an ingestion. Rejected: upgrading to Paid for a 16 GB instance (credits would be used faster, and the Free plan limit protects against surprise charges); a smaller instance (too little memory). Fallback if memory fails: upgrade to the Paid plan (credits stay valid 12 months from sign-up, checked 2026-10-29). The Free plan ends on 2027-04-29 and the account closes unless upgraded.
- **D-60 · Scope cut: CloudWatch moves to Phase 14; the budget alert is the cost control** (Accepted 2026-10-30; amends D-04). Phase 12 passed its limit of about 40 exchanges; CloudWatch needs a new IAM policy and a compose logging change, and no exit condition needs it. A cost budget (`monthly-cap`, $20 a month, email alerts) was created first instead. Why: monitoring belongs with Phase 14 (logging, alarms); the budget covers the cost risk. Revisit at Phase 14 (logs for the `api` container, one alarm). The Phase 12 cost measurement stayed **pending** (E-7).
